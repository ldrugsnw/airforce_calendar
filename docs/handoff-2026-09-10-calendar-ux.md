## 사용자가 직접 확인한 문제

### 1. 달력 단계 안내가 보이지 않음

휴가/외출을 고른 다음 시작일·종료일을 고르라는 안내가 없는 것처럼 느껴진다.

실제로 안내 문구는 `CalendarPage`의 달력 아래 패널에 있으나, 모바일에서는 달력이 길어서 화면 밖에 놓인다. 상태 변경과 안내가 공간적으로 분리된 것이 원인이다. 안내 문자열을 추가하는 수준보다 모바일 시선 흐름을 다시 설계해야 한다.

권장 방향:

1. 안내 영역을 휴가/외출 선택 버튼과 달력 사이에 고정한다.
2. 휴가 모드 초기 상태에는 `① 시작일을 선택하세요`를 표시한다.
3. 시작일 선택 후 같은 위치에서 `② 종료일을 선택하세요`로 즉시 바꾼다.
4. 하루 휴가는 같은 날짜를 다시 선택한다는 설명도 같은 위치에 표시한다.
5. 외출 모드는 `외출할 날짜 하루를 선택하세요`라고 명확히 표시한다.
6. 선택된 날짜와 취소 동작도 달력 가까이에 둔다.
7. 먼저 현재 구현을 모바일 뷰포트에서 확인한 뒤, 달력 관련 diff만 되돌릴지 새 흐름으로 수정할지 결정한다.

전체 롤백보다는 달력 상호작용 변경만 선택적으로 재검토하고 날짜 검증·선택 입력·색상 개선 등 독립 변경은 유지하는 방향이 권장된다.

### 2. 휴가 잔디가 모바일에서 너무 넓음

현재 범위는 오늘 기준 과거 6개월부터 미래 6개월 직전까지이며 가로 스크롤을 사용한다. 사용자는 모바일에서 좌우 스크롤이 불편하고 기능의 효용이 떨어진다고 평가했다.

다음 요구사항으로 변경한다:

- 표시 범위: 오늘 기준 `-10주`부터 `+10주`까지
- 총 20주 흐름을 한 화면 너비 안에 표시
- 가로 스크롤 제거
- 미래 일정은 계속 표시
- 휴가 종류별 색상과 접근 가능한 날짜 설명은 유지
- 정확한 경계는 구현 전에 테스트 문구로 고정한다. 권장 해석은 `[오늘 - 70일, 오늘 + 70일)`로 총 140일이며, 마지막 날짜는 `오늘 + 69일`이다.
- 작은 화면에서 20개 주 열이 실제로 들어가도록 셀 크기와 간격을 반응형으로 조절한다.

20주는 약 320px 안팎으로 구성할 수 있어 12개월보다 모바일에 적합하다. 단, 축소된 셀을 손가락으로 직접 누르는 UI로 만들기보다는 전체 패턴 확인용으로 두고 각 셀의 접근성 레이블을 유지한다.

## 서버와 DB 상황

- `.env`는 로컬 DB가 아니라 배포된 Supabase 프로젝트를 가리킨다.
- 새 마이그레이션 `202609100001_feedback_input_limits.sql`은 로컬 DB에만 적용했다.
- 배포 DB에는 아직 적용하지 않았다.
- 따라서 기존 5173 서버에서 획득일을 비워 저장하면 배포 DB의 기존 `NOT NULL` 제약에 걸려 일반 오류가 표시될 수 있다.
- 원격 DB 마이그레이션은 외부 상태 변경이므로 사용자 승인 없이 적용하지 않는다.
- 브라우저 localStorage 기반 테스트 서버를 5174 포트로 실행했다. 세션이 종료되면 다음 명령으로 다시 실행한다.

```bash
VITE_SUPABASE_URL= VITE_SUPABASE_PUBLISHABLE_KEY= npm run dev -- --host 0.0.0.0
```

이 모드는 로그인과 기기 간 동기화는 없지만 휴가 추가·수정·달력 흐름을 테스트할 수 있다.
